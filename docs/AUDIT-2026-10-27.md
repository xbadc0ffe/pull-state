## Tier 1 — user-visible bugs / data problems

### 1. Log screen state (including a running timer) is lost on tab switch
`MainTabView` renders the four tabs with a `switch selected { … }` inside a `Group`. SwiftUI destroys the `LogScreen` view when the tab changes, so every `@State` on it goes away: a running timer, `startInstant`, typed notes, rating, tags, photo, date. Switch to History mid-pull and the timer resets to READY.
**Fix:** keep all four tab screens alive and toggle visibility (`ZStack` + `.opacity`/`.zIndex`, or `.id`-stable views), or lift Log draft state into an `@Observable` object owned by `MainTabView`.

### 2. Recipe temperature on Bean detail / Add Bean ignores the °F preference
`RecipeBlock` hard-codes the unit as `"°C"` and writes the typed number straight into `Recipe.temp` (stored Celsius). `RecipeSheet` (from the Log screen) converts correctly via `RecipeTempField`. A Fahrenheit user who types `200` on the Bean detail recipe stores 200 °C, and the Log slider then clamps it to 105 °C.
**Fix:** give `RecipeBlock` the same `RecipeTempField` conversion (read `\.psTempUnit`), or share one row implementation between the two.

### 3. Select-all-on-focus also fires for multi-line Notes editors
`SelectAllOnFocus` observes `UITextView.textDidBeginEditingNotification`, so tapping into an existing shot/bean note selects the entire note and the first keystroke replaces it. Great for numeric fields, a data-loss trap for prose.
**Fix:** drop the `UITextView` observer (keep `UITextField`), or opt the `TextEditor`s out.

### 4. Full-resolution photos are decoded on the main thread for every thumbnail
Crops are saved as JPEG at the source pixel size (a 12 MP capture → ~3000×3000 px, 1–3 MB). `PSPhotoThumb` calls `UIImage(data:)` on every render for 32–78 pt thumbnails in History, Beans, Hardware and the Log pickers; `ShotCard` can decode two (shot + bean fallback). With a few dozen photographed shots this means scroll jank and large memory spikes.
**Fix:** downscale on save (e.g. max 1024 px edge) in `PSPhotoCropSheet.makeCroppedData`, and/or decode thumbnails with `UIImage.preparingThumbnail(of:)` off-main and cache by `persistentModelID`.

### 5. StoreKit: no `Transaction.updates` listener
Purchases that resolve outside the purchase call (Ask to Buy `.pending`, interrupted purchase, refund) are never observed or `finish()`ed, so StoreKit re-delivers them on every launch. `AboutSheet` does re-derive `hasTipped` from `currentEntitlements` on appear, which masks the UI side, but Apple's guidance is to always listen.
Also: `StoreManager` is created per `AboutSheet` instance (re-fetches the product each open), and a failed product load leaves a persistent red "Couldn't load tip product." line, which is what an offline user sees.
**Fix:** one app-scoped `StoreManager`, start a `Transaction.updates` task in `init`, and treat load failure as "price unavailable" rather than an error.

### 6. Fixed font sizes do not scale with Dynamic Type (docs claim they do)
`PSFont` uses `Font.system(size:weight:design:)`, which is a fixed point size. `Theme.swift` and DESIGN.md §5.2 state the opposite. Users with larger text settings get no scaling anywhere.
**Fix:** `Font.custom`/`.system(size:relativeTo:)` isn't available for system fonts, so use `@ScaledMetric` on the size values or `Font.system(.body/.title…)` with `.fontDesign(.serif/.monospaced)`.

### 7. Accessibility gaps
- `PSIconBtn` defaults its label to the SF Symbol name, so VoiceOver reads "ellipsis", "plus", "chevron.left" on most screens (only Log passes a label).
- `PSToggle` is a bare `Button`: no `.isToggle` trait, no on/off value.
- `SliderField` is not an adjustable element; the only accessible path is the tap-to-type readout.
- `PSTabBar` buttons lack `.isSelected`.
- Grind, dose, yield rows and tasting pills have no `accessibilityValue`.

## Tier 2 — correctness edge cases

### 8. Shot-edit sliders silently clamp values outside their range
`SliderField` displays `clampedValue`. Pull time range is 0–60 s and pre-infusion 0–20 s on the edit screen, but the Log screen accepts any timer value and manual entry up to 999 s. A 75 s pull shows as "60.0 s" in edit mode (and becomes 60 if the user touches the slider). Same for water temp outside 70–105 °C and pressure outside 4–12 bar.
**Fix:** widen edit ranges (match Log manual limits) or show the real value with the thumb pinned.

### 9. Fahrenheit slider step causes spurious "Adjust recipe?" prompts
In °F the slider steps by 1 °F (0.556 °C) while recipes store 0.5 °C steps. `evaluateRecipePrompt` compares temp with ε = 0.01, so a °F user who touches the slider at all differs from the recipe and gets the Adjust prompt on every best-rated shot.
**Fix:** compare temperature with a tolerance of ~0.6 °C (or compare in the display unit, rounded).

### 10. Rating 0 (unrated) shots distort charts and averages
`RatingChart` maps rating 0 to a y below the 1★ baseline (drawn outside the plot). `Bean.averageRating` and History "AVG ★" treat unrated shots as 0 stars.
**Fix:** exclude `rating == 0` from averages and the trend, or plot them as hollow markers on the baseline.

### 11. SwipeBackFix risks
`extension UINavigationController { override open func viewDidLoad() }` — overriding in an extension is unsupported Swift (it compiles only via the ObjC runtime) and it applies to every navigation controller in the process, including the camera `UIImagePickerController` and the Photos picker's internal stack. `gestureRecognizerShouldBegin` also returns true during push/pop transitions, the classic cause of a corrupted navigation stack.
**Fix:** at minimum add `transitionCoordinator == nil` to the check; longer term, use the iOS 18+ SwiftUI-native approach (`.toolbarVisibility(.hidden, for: .navigationBar)` keeps the gesture on recent OS versions — verify on iOS 26, which is the deployment target) and delete the shim.

### 12. `fatalError` if the SwiftData store fails to open
A corrupted or un-migratable store becomes a launch crash loop with no recovery path.
**Fix:** on failure, move the store aside and recreate (log nothing user-identifiable), or fall back to in-memory with a visible notice.

### 13. Catalog combobox may reopen after a selection
`OnbCombobox` has `.onChange(of: text) { open = true }`. Picking a suggestion sets `text = opt` then `open = false`; the `onChange` then fires and sets `open = true` again. Verify on device; if the list stays open after a pick, guard the `onChange` with a "did user type" flag.

### 14. Minor data hygiene
- `BeanAddForm.save` and `BeanDetailView.commitEdit` check the trimmed name for emptiness but store the untrimmed string (Hardware trims).
- `BeanRatingPoint.id` is the date; two shots with identical timestamps collide (harmless today because `ForEach` uses offsets).
- Onboarding shows a hard-coded "BAG #001".
- `settings.hasTipped = true` in `AboutSheet` relies on autosave; every other write site calls `context.save()`.

## Tier 3 — build configuration

### 15. Platforms you probably don't mean to ship
`SUPPORTED_PLATFORMS = iphoneos iphonesimulator macosx xros xrsimulator` and `TARGETED_DEVICE_FAMILY = 1,2,7` (7 = visionOS). README says iPhone/iPad only. The `ship` script builds iOS only, so the macOS/visionOS targets are never compiled, but App Store Connect may offer the iPad build on Vision Pro / Apple Silicon Macs unless you've opted out, and the `#if os(iOS)` shims exist only to keep an untested macOS build compiling.
**Fix:** trim to `iphoneos iphonesimulator` and family `1,2`, drop the macOS fallbacks, or consciously keep them and test.

### 16. Deployment target 26.4 excludes iOS 26.0–26.3
A deliberate choice is fine, but check App Store Connect analytics; 26.0 would cost nothing in this codebase.

### 17. StoreKit configuration is not in the shared scheme
README says the `.storekit` file is "wired into the scheme automatically in Debug builds". The shared `.xcscheme` has no `StoreKitConfigurationFileReference`, so Simulator tip-jar testing does not work out of the box.
**Fix:** add it to the scheme (Run → Options) and commit, or correct the README.

### 18. `MARKETING_VERSION` in the project drifts from what ships
`ship` passes `MARKETING_VERSION=1.5` on the command line; the pbxproj still says 1.4 afterwards. Bump the pbxproj as part of each release (done for 1.5 in this pass) so the repo matches TestFlight.

### 19. Swift language mode 5, `REGISTER_APP_GROUPS = YES`, `SWIFT_EMIT_LOC_STRINGS = YES` with no String Catalog
All harmless; noted so they are decisions rather than leftovers. Moving to Swift 6 mode is a worthwhile future cleanup given `SWIFT_APPROACHABLE_CONCURRENCY` is already on.

### 20. No test target
`Recipe` encode/decode, `TemperatureUnit` conversion, `evaluateRecipePrompt` rules, `FlowLayout`, `HardwareCatalog.brand(forName:)` and `PSFmt` are pure and cheap to cover. A single `Pull StateTests` target with Swift Testing would protect the recipe-prompt rules, which are the most intricate logic in the app.
